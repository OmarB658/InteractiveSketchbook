I was able to experiment a little bit but nothing I did really worked all too well. As a result, I don’t really have a good progress screenshot I can submit.

I’ve done a tiny bit of structural organization to somewhat reflect the current layout of my desktop interactive sketchbook homepage layout. Much of the details is incomplete but I’m sort of understanding how hierarchies work within HTML and CSS.

All the details and most of the basic layout are complete at the moment and none of the navigation works but I’m still in the progress of working on it.

It was really cool and interesting learning the behind the scenes of what makes an HTML website work and how Figma is able to be translated into HTMl and CSS.

One aspect of coding that has been surprising for me is the degree to which the browser determines placement of elements based on its default behavior. Elements do not simply show up in the locations where one would expect them to and spacing works very differently compared to Figma. One particular challenge was the difficulty of keeping proper alignment and spacing before learning the principles of flexbox and grids.

These are just some examples of a lot of assumptions about interface development that have been proved to be inaccurate by this experience. The design interface makes assumptions about the exact placement and location of items, but coding is about flexibility and flow rather than specific positioning. Meanwhile, HTML assumes an existing hierarchy, which is more important than positioning in design.

However, this experience has been quite fascinating nonetheless and it has allowed me to gain insight into translating designs from Figma into working websites.
